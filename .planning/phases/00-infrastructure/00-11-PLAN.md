  <name>Task 1: Provision nginx reload cron via install-vps-crons.sh</name>
  <files>scripts/install-vps-crons.sh, docker-compose.prod.yml, .github/workflows/ci-cd.yml</files>
  <action>
    Create `scripts/install-vps-crons.sh` — an idempotent script that installs the nginx post-renewal reload cron on the VPS. The certbot container does not have docker CLI access, so the reload must come from the host system via a cron job.

    Script requirements:
    - Shebang: `#!/bin/bash`
    - `set -e`
    - Detect the k21 install directory (default `/opt/k21`, override via `K21_DIR` env var):
      `K21_DIR="${K21_DIR:-/opt/k21}"`
    - Write a file `/etc/cron.d/k21-nginx-reload` with content:
      ```
      # Reload nginx after certbot renews the certificate
      # Must run AFTER certbot's 12h renewal loop (certbot runs renewal ~02:00 and 14:00)
      0 3 * * * root docker compose -f ${K21_DIR}/docker-compose.yml -f ${K21_DIR}/docker-compose.prod.yml exec -T nginx nginx -s reload >> /var/log/k21-nginx-reload.log 2>&1
      0 15 * * * root docker compose -f ${K21_DIR}/docker-compose.yml -f ${K21_DIR}/docker-compose.prod.yml exec -T nginx nginx -s reload >> /var/log/k21-nginx-reload.log 2>&1
      ```
    - Set cron file permissions to 644: `chmod 644 /etc/cron.d/k21-nginx-reload`
    - Print success message: `echo "Nginx reload cron installed at /etc/cron.d/k21-nginx-reload"`
    - Script is idempotent — running it multiple times overwrites the same file with no side effects

    In `docker-compose.prod.yml`, add a YAML comment block directly above the `certbot:` service key (do not change any functional YAML):
    ```yaml
      # Post-renewal nginx reload: the certbot container has no docker CLI, so nginx
      # cannot be reloaded from inside the container. A host cron job handles this.
      # Install it once (and on every deploy) via: bash scripts/install-vps-crons.sh
    ```

    In `.github/workflows/ci-cd.yml`, add a step in the SSH deploy script between Step 3 (docker compose up -d) and Step 4 (health check):
    ```bash
    # Step 3.5: Ensure VPS cron jobs are installed (idempotent)
    bash /opt/k21/scripts/install-vps-crons.sh
    echo "VPS crons installed."
    ```

    The `-T` flag on `docker compose exec` is required for non-interactive cron use (disables pseudo-TTY allocation, which would cause exec to hang in a headless context).
  </action>
