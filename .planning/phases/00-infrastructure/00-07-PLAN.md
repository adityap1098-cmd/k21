Netdata service config:

  pid: host                  # Required for process visibility
  volumes:
    - netdataconfig:/etc/netdata    # This volume holds netdata.conf
    - /proc:/host/proc:ro
    - /sys:/host/sys:ro

Key research finding:
  With network_mode: host, Netdata binds to ALL host interfaces by default.
  MUST set [web] bind to = 127.0.0.1 in netdata.conf to restrict to localhost.
  Access via: ssh -L 19999:localhost:19999 user@vps → http://localhost:19999

Log rotation already configured in docker-compose.yml:
  Every service has: logging.driver: json-file + max-size: 10m + max-file: 5
  This plan provides the verification tooling, NOT the configuration itself.

  <action>
    Create `netdata/netdata.conf` with the critical `bind to = 127.0.0.1` setting. This file is mounted into the `netdataconfig` volume by the Netdata container.

    Because the Netdata service uses `network_mode: host`, it has access to all host interfaces. Without this config, Netdata will bind to 0.0.0.0 and be accessible from the internet — a security violation.

    The `netdataconfig` volume in docker-compose.prod.yml maps to `/etc/netdata` inside the container. The netdata.conf file must be at `netdata/netdata.conf` in the repo and copied to the volume on first start.

    Update the Netdata service in `docker-compose.prod.yml` to mount the config file directly (add to existing Netdata volumes list):
    ```yaml
    # Add to netdata service volumes in docker-compose.prod.yml:
    - ./netdata/netdata.conf:/etc/netdata/netdata.conf:ro
    ```

    **netdata/netdata.conf**:
    ```ini
    # netdata/netdata.conf
    # K21 Netdata configuration
    # Mounted at /etc/netdata/netdata.conf in the Netdata container
    #
    # Access: SSH tunnel only
    #   ssh -L 19999:localhost:19999 user@vps
    #   Then open: http://localhost:19999

    [global]
      # Run as netdata user (default)
      run as user = netdata

      # Memory mode: save — persist metrics across restarts
      memory mode = save

      # History: 3600 seconds (1 hour) of per-second metrics
      history = 3600

    [web]
      # CRITICAL: Bind to localhost ONLY — never expose to internet
      # With network_mode: host, this prevents external access
      bind to = 127.0.0.1

      # Port
      default port = 19999

      # Disable Netdata Cloud telemetry/sign-in prompts
      allow dashboard from = localhost

    [plugins]
      # Enable Docker container monitoring
      cgroups = yes
      proc = yes
      diskspace = yes
      netlink = yes

    [logs]
      # Log to stdout so docker logs works
      error log = /var/log/netdata/error.log
      access log = /var/log/netdata/access.log
      debug log = /var/log/netdata/debug.log
    ```

    Also update `docker-compose.prod.yml` to add the config volume mount to the netdata service. Open `docker-compose.prod.yml` (created in Plan 00-03) and append to the netdata service volumes:

  <action>
    Log rotation is configured in docker-compose.yml via the `logging` block on every service. The verification script confirms that every running container actually has this config active.

    **scripts/verify-log-rotation.sh**:
    ```bash
    #!/bin/sh
    # scripts/verify-log-rotation.sh
    # Verifies that Docker log rotation is active on all running K21 containers.
    # Run on the VPS after deployment: sh scripts/verify-log-rotation.sh
    #
    # Expected output for each container:
    #   PASS: <container-name> — json-file max-size=10m max-file=5
    # Fail if any container shows a different log driver or missing options.

    set -e

    FAIL=0
    EXPECTED_MAX_SIZE="10m"
    EXPECTED_MAX_FILE="5"

    echo "=== K21 Log Rotation Verification ==="
    echo ""

    # Get all running K21 containers (those with k21 in name)
    CONTAINERS=$(docker ps --format '{{.Names}}' | grep -i k21 || true)

    if [ -z "$CONTAINERS" ]; then
      echo "WARNING: No K21 containers are running. Start the stack first."
      echo "  docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d"
      exit 1
    fi

    for CONTAINER in $CONTAINERS; do
      # Get log driver type
      LOG_DRIVER=$(docker inspect "$CONTAINER" \
        --format '{{.HostConfig.LogConfig.Type}}' 2>/dev/null || echo "unknown")

      # Get log options
      MAX_SIZE=$(docker inspect "$CONTAINER" \
        --format '{{index .HostConfig.LogConfig.Config "max-size"}}' 2>/dev/null || echo "none")

      MAX_FILE=$(docker inspect "$CONTAINER" \
        --format '{{index .HostConfig.LogConfig.Config "max-file"}}' 2>/dev/null || echo "none")

      if [ "$LOG_DRIVER" = "json-file" ] && \
         [ "$MAX_SIZE" = "$EXPECTED_MAX_SIZE" ] && \
         [ "$MAX_FILE" = "$EXPECTED_MAX_FILE" ]; then
        echo "PASS: $CONTAINER — $LOG_DRIVER max-size=${MAX_SIZE} max-file=${MAX_FILE}"
      else
        echo "FAIL: $CONTAINER — driver=${LOG_DRIVER} max-size=${MAX_SIZE} max-file=${MAX_FILE}"
        FAIL=1
      fi
    done

    echo ""
    if [ "$FAIL" -eq 0 ]; then
      echo "=== ALL CONTAINERS HAVE CORRECT LOG ROTATION ==="
    else
      echo "=== SOME CONTAINERS HAVE INCORRECT LOG ROTATION ==="
      echo "Fix: Recreate containers with 'docker compose up -d --force-recreate'"
      exit 1
    fi
    ```

    Make executable: `chmod +x scripts/verify-log-rotation.sh`
