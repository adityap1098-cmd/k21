Opname flow (from research Pattern 6):
- Receive array: { variantId, physicalCount }[]
- FOR EACH variant: SELECT stock_qty FOR UPDATE, compute discrepancy = physicalCount - stock_qty
- If discrepancy != 0: insert ADJUSTMENT movement + UPDATE stock_qty = physicalCount
- approvedBy = performedBy (v1 decision: opname performer is also the approver)
- reference = `OPNAME-{opnameId}` (opnameId = randomUUID() generated once per batch)

**opname.service.ts:**
```typescript
import { randomUUID } from 'crypto'
import { sql } from 'drizzle-orm'
import { db } from '../../db/index.js'
import { recordMovement } from './movement.service.js'
import { invalidateStockCache } from './stock.service.js'

export async function runStockOpname(params: {
  items: Array<{ variantId: string; physicalCount: number }>
  performedBy: string
  ipAddress: string
}): Promise<{ adjustments: number; opnameId: string }> {
  const opnameId = randomUUID()
  const adjustedVariantIds: string[] = []

  await db.transaction(async (tx) => {
    for (const item of params.items) {
      const rows = await tx.execute(
        sql`SELECT id, stock_qty FROM product_variants WHERE id = ${item.variantId} FOR UPDATE`
      )
      const variant = rows[0] as { id: string; stock_qty: number } | undefined
      if (!variant) continue  // skip missing variants rather than failing entire batch

      const discrepancy = item.physicalCount - variant.stock_qty
      if (discrepancy === 0) continue

      await recordMovement({
        variantId: item.variantId,
        movementType: 'ADJUSTMENT',
        qty: Math.abs(discrepancy),  // recordMovement handles sign for ADJUSTMENT (positive)
        reference: `OPNAME-${opnameId}`,
        reason: `Stock opname ${opnameId}`,
        approvedBy: params.performedBy,  // v1: performer is approver
        performedBy: params.performedBy,
      }, tx)

      // Note: ADJUSTMENT qty sign — for opname, physicalCount is the target.
      // If discrepancy > 0: adding stock (positive ADJUSTMENT)
      // If discrepancy < 0: removing stock (negative ADJUSTMENT)
      // recordMovement applies Math.abs then sign based on type;
      // ADJUSTMENT keeps positive qty. We need to set exact physicalCount:
      await tx.execute(
        sql`UPDATE product_variants SET stock_qty = ${item.physicalCount}, updated_at = now() WHERE id = ${item.variantId}`
      )
      adjustedVariantIds.push(item.variantId)
    }
  })

  // Invalidate cache for all adjusted variants after transaction
  await Promise.all(adjustedVariantIds.map(id => invalidateStockCache(id)))

  return { adjustments: adjustedVariantIds.length, opnameId }
}
```

Important note about recordMovement qty handling for ADJUSTMENT: The current recordMovement implementation applies `Math.abs(qty)` for ADJUSTMENT type. For opname, we pass `Math.abs(discrepancy)` as qty so recordMovement stores the absolute value. The actual stock correction is handled by the explicit UPDATE statement setting `stock_qty = physicalCount`. This is correct — the movement records the magnitude of change, the UPDATE sets the authoritative value.

**lowstock.service.ts:**
```typescript
import { randomUUID } from 'crypto'
import { eq, inArray } from 'drizzle-orm'
import { db } from '../../db/index.js'
import { users, notifications } from '../../db/schema/index.js'

export async function processLowStockAlert(params: {
  variantId: string
  currentStock: number
}): Promise<number> {
  const admins = await db
    .select({ id: users.id })
    .from(users)
    .where(
      // Owner or Admin, active
      inArray(users.role, ['Owner', 'Admin'])
    )
    .where(eq(users.isActive, true))

  if (admins.length === 0) return 0

  await db.insert(notifications).values(
    admins.map(user => ({
      id: randomUUID(),
      userId: user.id,
      type: 'LOW_STOCK',
      payload: { variantId: params.variantId, currentStock: params.currentStock },
      readAt: null,
      createdAt: new Date(),
    }))
  )

  return admins.length
}
```
