# Plan 06-01: Marketplace Schema + Test Stubs

**Wave 0 — Foundation**

## Goal

Create the database schema for marketplace integration and RED-state test stubs for all MKT requirements.

## Tasks

### Task 1: Drizzle Schema + Migration SQL

Create `apps/api/src/db/schema/marketplace.ts` with:

**Enums:**
- `marketplace_platform`: `SHOPEE`, `TIKTOK`
- `marketplace_order_status`: `PENDING`, `CONFIRMED`, `READY_TO_SHIP`, `SHIPPED`, `DELIVERED`, `COMPLETED`, `CANCELLED`, `RETURN`
- `webhook_event_status`: `RECEIVED`, `PROCESSING`, `PROCESSED`, `FAILED`, `SKIPPED`
- `sync_status`: `SYNCED`, `PENDING`, `FAILED`, `UNMAPPED`

**Tables:**

```
marketplace_tokens
  id              UUID PK
  platform        marketplace_platform NOT NULL
  shopId          VARCHAR(100) NOT NULL
  shopName        VARCHAR(255)
  shopCipher      VARCHAR(255)          -- TikTok-specific
  accessToken     TEXT NOT NULL
  refreshToken    TEXT NOT NULL
  accessExpiresAt TIMESTAMPTZ NOT NULL
  refreshExpiresAt TIMESTAMPTZ NOT NULL
  metadata        JSONB                 -- extra platform data
  createdAt       TIMESTAMPTZ
  updatedAt       TIMESTAMPTZ
  UNIQUE (platform, shopId)

webhook_events
  id              UUID PK
  platform        marketplace_platform NOT NULL
  eventType       VARCHAR(100) NOT NULL
  eventId         VARCHAR(255) NOT NULL
  rawPayload      JSONB NOT NULL
  status          webhook_event_status NOT NULL DEFAULT 'RECEIVED'
  processedAt     TIMESTAMPTZ
  errorMessage    TEXT
  retryCount      INTEGER DEFAULT 0
  createdAt       TIMESTAMPTZ
  UNIQUE (platform, event_type, event_id)   -- MKT-07 dedup

marketplace_orders
  id                  UUID PK
  platform            marketplace_platform NOT NULL
  platformOrderId     VARCHAR(255) NOT NULL
  platformOrderSn     VARCHAR(255)          -- Shopee order_sn
  status              marketplace_order_status NOT NULL DEFAULT 'PENDING'
  buyerUsername        VARCHAR(255)
  shippingAddress     JSONB
  orderTotal          NUMERIC(15,2) NOT NULL
  platformFees        NUMERIC(15,2) DEFAULT 0
  platformData        JSONB                 -- full raw order data
  reservationId       UUID                  -- FK to stock_reservations (nullable until confirmed)
  journalEntryId      UUID                  -- FK to journal_entries (nullable until shipped)
  createdAt           TIMESTAMPTZ
  updatedAt           TIMESTAMPTZ
  UNIQUE (platform, platformOrderId)

marketplace_order_items
  id                  UUID PK
  marketplaceOrderId  UUID NOT NULL FK → marketplace_orders
  platformItemId      VARCHAR(255) NOT NULL
  platformModelId     VARCHAR(255)          -- variant-level
  variantId           UUID                  -- FK to product_variants (nullable if unmapped)
  sku                 VARCHAR(100)
  itemName            VARCHAR(500) NOT NULL
  qty                 INTEGER NOT NULL
  unitPrice           NUMERIC(15,2) NOT NULL
  createdAt           TIMESTAMPTZ

marketplace_listings
  id              UUID PK
  platform        marketplace_platform NOT NULL
  platformItemId  VARCHAR(255) NOT NULL
  platformModelId VARCHAR(255)
  variantId       UUID NOT NULL           -- FK to product_variants
  syncStatus      sync_status NOT NULL DEFAULT 'PENDING'
  lastSyncedAt    TIMESTAMPTZ
  lastStockPushed INTEGER
  createdAt       TIMESTAMPTZ
  updatedAt       TIMESTAMPTZ
  UNIQUE (platform, platformItemId, platformModelId)
```

Write migration SQL as `apps/api/drizzle/0014_marketplace_schema.sql`.

Export from `apps/api/src/db/schema/index.ts`.

### Task 2: RED Test Stubs

Create/replace `apps/api/src/modules/marketplace/marketplace.test.ts` with RED-state stubs covering:

- **Webhook dedup (MKT-07):** duplicate webhook with same `(platform, eventType, eventId)` is skipped
- **Webhook HMAC verification (MKT-06):** invalid signature returns 401
- **Webhook handler returns 200 < 100ms (MKT-06):** handler stores + enqueues without processing
- **Order import (MKT-01, MKT-02):** Shopee/TikTok order webhook creates marketplace_order record
- **Stock reservation on confirm (MKT-04):** confirmed order creates stock reservation
- **Cancel releases reservation (MKT-04):** cancelled order releases reservation
- **Ship converts to movement + journal (MKT-04):** shipped order converts reservation to inventory_movement(SALE) + journal entry
- **Outbound stock sync (MKT-03):** inventory change triggers stock push to marketplace
- **Token refresh (MKT-08):** expired token triggers refresh; failed refresh alerts
- **Polling fallback (MKT-05):** cron job fetches recent orders as safety net

All stubs should import from not-yet-created service files and fail (RED state). The test file must be parseable by vitest without crashing.

## Verification

- `pnpm --filter @k21/api exec vitest run` passes (stubs fail gracefully, suite doesn't crash)
- Migration SQL is valid PostgreSQL
- Schema exports compile: `pnpm --filter @k21/api exec tsc --noEmit`
