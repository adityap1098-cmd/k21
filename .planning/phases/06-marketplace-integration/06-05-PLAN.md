# Plan 06-05: Order Lifecycle Workers

**Wave 3 — Order State Transitions**

## Goal

Handle order lifecycle events: cancel releases reservation, ship converts to movement + journal, complete finalizes.

## Tasks

### Task 1: Order Lifecycle Service

Create `apps/api/src/modules/marketplace/order-lifecycle.service.ts`:

**`handleOrderCancelled(orderId)`:**
1. Load marketplace_order → verify status allows cancellation
2. Release all stock reservations for this order via `releaseReservation(reservationId)`
3. Update marketplace_order status → CANCELLED
4. Audit log

**`handleOrderShipped(orderId)`:**
1. Load marketplace_order + items with mapped variantIds
2. For each mapped item:
   - Convert reservation to `inventory_movement(SALE)` via `recordMovement({ variantId, movementType: 'SALE', qty: -item.qty, reference: 'MKT-{platform}-{platformOrderId}' })`
   - Release the reservation after movement recorded
3. Create journal entry stub with sourceType `MARKETPLACE_SALE` and order total
   - **Note:** `journal_entries.transactionId` FK points to POS `transactions.id`. For marketplace, either:
     - (a) Create a "ghost" transaction record in POS transactions table (messy)
     - (b) Make `transactionId` nullable or remove FK, use `sourceId` + `referenceId` instead
     - **Decision to make at implementation time** — prefer (b) to keep marketplace decoupled from POS
4. Update marketplace_order status → SHIPPED
5. Invalidate stock cache for affected variants

**`handleOrderCompleted(orderId)`:**
1. Update marketplace_order status → COMPLETED
2. Log completion

**`handleOrderReturn(orderId, items)`:**
1. Reverse inventory movements (create RETURN movements)
2. Reverse journal entry
3. Update status → RETURN

### Task 2: Wire to Webhook Worker

Extend `order-import.worker.ts` to dispatch by event type:
- `order_status_push` / order status change → check new status → call appropriate handler
- Map platform-specific statuses to K21 lifecycle methods

### Task 3: Tests

- Cancel: reservation released, status → CANCELLED
- Ship: reservation → movement(SALE) + journal entry, status → SHIPPED
- Complete: status → COMPLETED
- Return: reverse movement + journal
- Invalid transition (e.g. ship a cancelled order) → throws error
- Stock cache invalidated after ship

## Verification

- All lifecycle tests GREEN
- End-to-end: webhook(CANCELLED) → reservation released
- End-to-end: webhook(SHIPPED) → movement + journal created
