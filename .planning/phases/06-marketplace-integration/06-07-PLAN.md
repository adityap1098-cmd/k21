# Plan 06-07: Polling Fallback

**Wave 4 — Safety Net for Missed Webhooks**

## Goal

BullMQ cron jobs that poll Shopee and TikTok order APIs as a safety net. Webhooks are the primary path; polling catches any missed events.

## Tasks

### Task 1: Polling Service

Create `apps/api/src/modules/marketplace/polling.service.ts`:

**`pollShopeeOrders(tokenRecord)`:**
1. Read `lastPolledAt` from `tokenRecord.metadata`
2. Call Shopee `order/get_order_list` with time range `[lastPolledAt, now]`
3. For each order: check if `marketplace_orders` already has `(SHOPEE, platformOrderId)`
4. If missing: call `importMarketplaceOrder()` (same as webhook path)
5. Update `lastPolledAt` in token metadata

**`pollTiktokOrders(tokenRecord)`:**
- Same pattern, different API endpoint

### Task 2: Polling Workers

Create `apps/api/src/modules/marketplace/workers/polling.worker.ts`:
- BullMQ repeatable job: `marketplace.poll-orders` every 5 minutes
- For each ACTIVE token: call the appropriate polling service
- Skip tokens with status != ACTIVE or access_token expired
- Log count of new orders found per poll

### Task 3: Tests

- Poll finds new order not in DB → imports it
- Poll finds existing order → skips
- Poll updates lastPolledAt timestamp
- Expired token → skip polling for that shop
- Empty response → no-op, timestamp updated

## Verification

- All polling tests GREEN
- Polling + webhook dedup: same order from both paths → only one record
