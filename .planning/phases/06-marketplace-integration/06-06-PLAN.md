# Plan 06-06: Outbound Stock Sync

**Wave 4 — Stock Push to Marketplaces**

## Goal

When inventory changes in K21 (any source: POS sale, procurement receive, opname adjustment), push updated stock to Shopee and TikTok.

## Tasks

### Task 1: Stock Sync Service

Create `apps/api/src/modules/marketplace/stock-sync.service.ts`:

**`enqueueStockSync(variantId)`:**
- Called by inventory module after any stock change
- Enqueue BullMQ job `marketplace.sync-stock` with `{ variantId }`
- Use BullMQ job dedup: `jobId: stock-sync-${variantId}` with 5-second delay (debounce rapid changes)

**`syncStockToMarketplaces(variantId)`:**
1. Get current stock for variant (from DB, not cache — cache may be stale)
2. Find all `marketplace_listings` where `variantId = X` and `syncStatus = SYNCED`
3. For each listing:
   - Call platform API to update stock (Shopee `update_stock`, TikTok `product/stocks`)
   - On success: update `lastStockPushed` and `lastSyncedAt`
   - On failure: log error, mark listing `syncStatus = FAILED`, retry via BullMQ

### Task 2: Wire to Inventory Module

Add hook in `apps/api/src/modules/inventory/movement.service.ts`:
- After `recordMovement()` succeeds, call `enqueueStockSync(variantId)` if marketplace module is active
- Use dynamic import or event pattern to avoid hard dependency from inventory → marketplace

### Task 3: Stock Sync Worker

Create `apps/api/src/modules/marketplace/workers/stock-sync.worker.ts`:
- BullMQ worker for `marketplace.sync-stock` queue
- Calls `syncStockToMarketplaces(variantId)`
- Retry: 3 attempts with exponential backoff (1s, 5s, 15s)
- On permanent failure: enqueue notification alert

### Task 4: Tests

- Stock change → BullMQ job enqueued with correct variantId
- Sync to Shopee: mock HTTP → verify update_stock called with correct model_id + qty
- Sync to TikTok: mock HTTP → verify product/stocks called
- Failed push: retries, marks listing as FAILED
- Variant with no marketplace_listings: no-op
- Debounce: multiple rapid changes → only one sync job
